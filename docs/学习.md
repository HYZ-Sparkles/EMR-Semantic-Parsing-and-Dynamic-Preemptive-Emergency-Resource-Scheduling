## Rust语法
- `map()` 将播报作用到容器内部的值上并且返回一个新的容器
- `and_then()` 闭包返回的就是`Option()`，不进行额外包装
- 函数参数
  - 如果含有堆上的数据，那么传入参数如果直接传入就是所有权转移。
  - 引用需要考虑外部数据本身是否mut，但是直接传入不需要考虑
- type 给类型定义别名
- impl中使用self相关参数代表struct实例内部字段的使用方法。
  - &self 不可变引用实例；&mut self 可变引用实例
  - self 转移所有权使用实例
  - 只有方法调用者才可以自动引用，函数参数需要显式引用
- 'static 
  - &'static 引用生命周期
    - `let s: &'static str = "Hello, world!"; // 这个引用永远有效`
  - T:'static 泛型约束 表示该变量含有所有权，不含有其他变量的引用
- trait Rust中对新创建类型的功能拓展
- derive Rust中的代码自动生成器
  - 使用其进行trait的自动生成时需要新类型的字段都实现对应的trait才可以
- 泛型 <T: Trait>：写代码时用“占位符”，加约束是为了让编译器允许你在代码里调用该 Trait 的方法（比如比较）。
- [...] 属性语法，在编译阶段执行，用来生成或修改你写的代码。
  - 派生宏：#[derive(Debug, Clone)]。
  - 函数/模块属性：#[tokio::main]。
  - 配置/标记属性：#[serde(rename = "userName")]。
- Axum 路由注册
- 异步与tokio
  - 写 async fn，在里面遇到耗时操作就 .await，要并发就 spawn 或 join!。
  - Arc 多线程安全下的对同一个变量的修改。
  - RwLock 读写锁。使用块来尽可能快速释放锁。
- 前后端通信(axum)
  - `layer(CorsLayer::permissive())` 为路由增加一层处理层，配置相应跨域请求。这里是允许所有跨域。在前端vite的代理配置后可以安全去除。
  - `State(s): State<AppState>`
    - 左边：元组结构体的解构
    - 右边：告诉 axum 的路由状态(Router State)中提取一个类型为 AppState 的数据。
  - WebSocketUpgrade 
- 注释相关
  - `//` 普通注释(内部使用)
  - `///` 函数或者结构体注释(写给外部使用者)
  - `//!` 文件注释(写给外部使用者)

## 前端语法
- 传统网页
  - HTML 页面的骨架(结构)；CSS 样式/皮肤；JavaScript 逻辑/行为
- Vue 
  - Vue文件同时包含了 HTML（模板）、CSS（样式）和 JS（逻辑），但 Vue 在底层做了“响应式绑定”
  - 在编译进入浏览器的时候vue文件都会被转换成为js代码。template和style会默认导出。
  - `fetch(url,option)` 发出网络请求获取数据
    - Option中可选进行method、header、body的配置。默认是Get方法
  - `<ControlBar :snapshot="snapshot" @admitted="onChanged" />`
    - `ControlBar` Vue自定义组件
    - `:shnapshot` 子组件内部期望的变量名
    - `"snapshot"` 父组件定义的响应式数据
    - `@admitted="onChanged"` @表示监听admitted事件。一旦发生就执行OnChanged函数
  - import 不加大括号对应取默认的公有并取别名；`{name}` 严格对应变量名为name的公有变量
  - export 公有变量外部可见(默认都是私有)。
    - `<script setup>` 对应自动补全的默认导出
  - vue指令 后引号内跟着变量
    - `v-if` 根据变量的值判断元素是否显示，不显示页面会直接消失。`v-show` 通过css样式控制是否展示
    - `v-model` 双向绑定
    - `v-for` 遍历
  - props：子组件中的性质，父组件用来把数据传递给子组件的“入口”
    - 子组件使用`const props=defineProps(['name','color'])`定义
    - 父组件直接传入即可
    - 子组件绝对不能直接修改 props 的值 
  - 子组件也可以向父组件传值
    - `const emit = defineEmits(['add','change'])` 子组件中定义可以触发的事件包括add和change
    - `emit(add,10)` 子组件中合适位置说明触发add事件，并且加的参数是10
    - `@add="addnum"` 父组件中监听add事件，发生则执行addnum函数，参数为事件发生的传递的参数
  - `watch(var,func)` 监听var，如果值变化就执行func
- TypeScript 加了类型注解和编译检查的js，但在编译之后会被处理成为js代码
- Vite 前端构建工具
  - 可以用来创建项目 `npm create vue@latest my-project`
  - 开发环境运行 `npm run dev`
  - 生产构建 `npm run build` `npm run preview`
  - 核心配置文件 `vite.config.ts`
    - 代理（Proxy）—— 解决 CORS
    - 路径别名（Alias）
  - Vite 使用 .env 文件区分开发/生产环境。
- HTML
  - class 属性，帮助css和js定位元素。可以多个元素属于同一class
  - id 唯一标识，每个元素一个
- CSS
  - @media(condition){...} 媒体响应，后面跟着条件判断
  - var(--XX) CSS中定义的变量
  - id使用`#`；class使用`.`
- 层叠优先级 首先以具体元素为准，然后按照css中id,class,标签选进行选择。
- const 变量：不能重新赋值。但是内部元素可以修改
- js中数据类型：
  - 基本数据类型：数字(整数、浮点数)、字符串、布尔值、null、symbol等
    - 字符串不可以修改
    - 
  - 引用数据类型：普通对象、数组、函数等
    - 普通对象的key只可以是字符串或者symbol，如果是`1:2`会转换成`"1":2`
## 算法设计
- 线段树
  - 支持插入医学词汇构建树和给定文本进行文本中医学词汇的查询。
- 位置索引的最大堆
  - 使用vec构建最大堆按照危险分数(score)存储内部病人(Entry)状况字段，使用hashmap对应病人id和最大堆中的下标位置。
  - 支持插入元素，弹出堆顶元素，按照病人id更新score，根据id删除元素，时间复杂度都是O(logn)，但是返回排序好的快照，时间复杂度O(nlogn)
- 医疗资源状态表
  - 使用vec存储所有医疗资源的情况，状态重点存储了医疗资源的种类，医疗资源的使用状态，使用的患者的id以及剩余使用时间，还有挂起的患者(使用列表实现，考虑恶化加分和后进患者危险分更高)。
  - 支持按照种类查询目前空闲的医疗资源或者寻找分数最小的占用
- 调度算法
  - 代码中调度过程：
    1. 患者到来(预约则考虑到来时间)
    2. 按照病情描述计算患者的危险分数、医疗场所选择危险分数最大的病情所需的场所(进行了简化)
    3. 尝试直接分配医疗资源，分配空闲医疗资源或者抢占同类资源中分数最小的(抢占存在危险分容忍度)
    4. 模拟治疗过程：危险分越高所需要治疗时间越长。
       1. 记录被治疗患者的治疗时间，可观测治疗的进度，如果被抢占则记录此时治疗的进度并加入挂起队列
       2. 医疗资源的挂起队列和最大堆中患者不断恶化
       3. 在某个医疗资源治疗完成后优先进行挂起队列的患者的治疗——挂起队列危险分数大于最大堆

## 改进想法
- 对于病人的描述大多是模糊的，应该要么分词规范化处理、要么一开始就是选择。如果一开始就是选择，那么线段树也可以简化处理。
- 如果对于病人的描述带有否定意味词汇应该怎么解决？
- 数据结构的范围是否造成浪费
  - Entry.arrive_tick:u64
- 对于多个病情的病人可能需要多个医疗资源的占用
- 数据变量的冗余，感觉可以借鉴数据库中的3NF进行优化。
  - “数据分散”
  - 似乎可以创建几个核心表存储所有数据，利用Rust的特性进行需要字段的所有权的借用就可以
- schedule的寻找同类空闲存在bug
  - treatment_ticks
- 接口parse是多余的，实际上只需要确认接收病人即可，而且病人可以预约进入医院
- 多个病情的病人此时是从最危险的病选择治疗场所的，应该可以改进。
- 挂起队列按照需求进行优化
- 在大型医院资源较多时可以考虑保留少数资源来随时应对高危患者的治疗
